# מתזמן משימות: מדריך מלא למבנה ה-JSON של משימה

המסמך הזה מתאר בדיוק איך כותבים משימה למתזמן. אפשר לתת אותו כמו שהוא ל-AI ולבקש ממנו לכתוב משימה.

## הוראות ל-AI

כשמבקשים ממך ליצור משימה למתזמן הזה:

1. החזר **אובייקט JSON אחד** במבנה שמתואר כאן, בלי הערות בתוך ה-JSON.
2. השתמש רק בשדות ובערכים שמופיעים במסמך. שדה לא מוכר יתעלם או יגרום לשגיאה.
3. כל הזמנים הם **שעון ישראל**, בפורמט `HH:MM` (24 שעות). תאריכים בפורמט `YYYY-MM-DD`.
4. אם השירות עונה 200 גם כשיש שגיאה, מלא את `success.must_contain` ו/או `success.error_words` לפי מבנה התשובה שלו.
5. כתוב את תוכן המיילים בעברית פשוטה וברורה, לאנשים שלא מבינים בטכנולוגיה. אל תכניס למייל קודים, JSON או מונחים טכניים, אלא אם ביקשו.
6. אם חסר לך פרט (מפתח API, כתובת מייל, מספר שלוחה), שים ערך ברור שצריך להחליף, כמו `YOUR_API_KEY` או `office@your-domain.com`, וציין זאת בתשובה.
7. אחרי ה-JSON, הסבר בשתיים-שלוש שורות מה המשימה עושה ומה צריך להחליף.

---

## המבנה הכללי

```json
{
  "name": "שם המשימה",
  "enabled": true,
  "schedule": { },
  "request": { },
  "success": { },
  "rules": [ ]
}
```

| שדה | חובה | תיאור |
|---|---|---|
| `name` | כן | שם המשימה, עד 200 תווים |
| `enabled` | לא | `true` (ברירת מחדל) = פעילה. `false` = מושבתת |
| `schedule` | כן | מתי להריץ. ראה "schedule" |
| `request` | כן | לאיזו כתובת לפנות. ראה "request" |
| `success` | לא | מתי התשובה נחשבת הצלחה. ראה "success" |
| `rules` | לא | אילו מיילים לשלוח לפי התוצאה. ראה "rules" |

## schedule: מתי להריץ

יש חמישה סוגים (`type`).

### 1. מועדים מסוימים: `dates`

```json
{ "type": "dates", "dates": ["2026-11-03 10:30", "2026-11-05 18:00"] }
```

- כל מועד בפורמט `"YYYY-MM-DD HH:MM"`.
- המשימה רצה פעם אחת בכל מועד, ואחרי המועד האחרון מושבתת לבד.
- לא ניתן לשמור משימה פעילה שכל המועדים שלה כבר עברו.

### 2. כל יום / ימים נבחרים: `daily`

```json
{ "type": "daily", "times": ["08:00", "20:00"], "days": [0, 1, 2, 3, 4] }
```

- `times`: שעה אחת או יותר.
- `days`: ימים בשבוע. 0 = ראשון, 1 = שני, 2 = שלישי, 3 = רביעי, 4 = חמישי, 5 = שישי, 6 = שבת. בלי השדה = כל יום.

### 3. כל חודש: `monthly`

```json
{ "type": "monthly", "calendar": "gregorian", "day": 1, "times": ["09:00"] }
{ "type": "monthly", "calendar": "hebrew", "day": 1, "times": ["07:00"] }
```

- `calendar`: `"gregorian"` (לועזי, ברירת מחדל) או `"hebrew"` (עברי).
- `day`: יום בחודש. בלועזי 1-31, בעברי 1-30.
- יום שלא קיים בחודש נופל על היום האחרון של החודש: 31 בחודש של 30 יום, או ל׳ בחודש עברי של 29 יום.

### 4. כל שנה: `yearly`

```json
{ "type": "yearly", "calendar": "gregorian", "month": 3, "day": 15, "times": ["09:00"] }
{ "type": "yearly", "calendar": "hebrew", "month": "shevat", "day": 15, "times": ["10:00"] }
```

- בלוח לועזי, `month` הוא מספר 1-12.
- בלוח עברי, `month` הוא אחד מהערכים הבאים (אפשר גם בשם העברי):

| ערך | חודש |
|---|---|
| `tishrei` | תשרי |
| `cheshvan` | חשוון |
| `kislev` | כסלו |
| `tevet` | טבת |
| `shevat` | שבט |
| `adar` | אדר (בשנה מעוברת: אדר ב׳) |
| `adar1` | אדר א׳ (בשנה פשוטה: אדר) |
| `adar2` | אדר ב׳ (בשנה פשוטה: אדר) |
| `nisan` | ניסן |
| `iyar` | אייר |
| `sivan` | סיוון |
| `tammuz` | תמוז |
| `av` | אב |
| `elul` | אלול |

- 29 בפברואר בשנה שאינה מעוברת נופל על 28 בפברואר.
- התאריך העברי נקבע לפי היום האזרחי (מחצות), לא לפי השקיעה.

### 5. כל כמה דקות: `interval`

```json
{ "type": "interval", "minutes": 30, "from": "08:00", "to": "20:00", "days": [0, 1, 2, 3, 4] }
```

- `minutes`: אחד מהערכים 1, 2, 5, 10, 15, 20, 30, 60, 120, 180, 240, 360, 720.
- הריצות מיושרות לשעון. למשל כל 30 דקות = 08:00, 08:30, 09:00...
- `from` / `to`: טווח השעות. ברירת מחדל: כל היום.
- `days`: כמו ב-`daily`.

### טווח תאריכים (לכל הסוגים החוזרים)

```json
"start_date": "2026-11-01",
"end_date": "2027-06-30"
```

רשות. המשימה תרוץ רק בין התאריכים האלה (כולל).

## request: הבקשה

```json
{
  "method": "GET",
  "url": "https://api.example.com/path?key=value",
  "headers": { "Authorization": "Bearer YOUR_API_KEY" },
  "body": "",
  "timeout_seconds": 30,
  "retries": 2
}
```

| שדה | ברירת מחדל | תיאור |
|---|---|---|
| `method` | `GET` | `GET`, `POST`, `PUT`, `PATCH` או `DELETE` |
| `url` | חובה | כתובת מלאה שמתחילה ב-`https://` או `http://`. אפשר לשלב משתנים |
| `headers` | `{}` | אובייקט של כותרות, למשל מפתח API |
| `body` | `""` | גוף הבקשה (לא נשלח ב-GET). טקסט, או אובייקט JSON |
| `timeout_seconds` | 30 | כמה שניות לחכות לתשובה (1-120) |
| `retries` | 2 | כמה פעמים לנסות שוב כשאין תשובה או שקוד התשובה לא תקין (0-4) |

- **body כ-JSON:** כשהגוף הוא JSON, המשתנים מוחלפים בתוך הערכים בצורה בטוחה. גרשיים או שורה חדשה בערך לא ישברו את ה-JSON.
- **Content-Type:** נקבע אוטומטית (`application/json` או טקסט), אלא אם הגדרת אותו ב-`headers`.
- **ניסיונות חוזרים:** ההמתנה בין הניסיונות היא 2 שניות, אחר כך 4, אחר כך 8.
- **מתי לא מנסים שוב:** כשהכשל זוהה לפי התוכן (`error_words` או `must_contain`), כי השרת ענה בבירור.

## success: מתי זה נחשב הצלחה

```json
{
  "status": "200-299",
  "error_words": ["error", "\"success\":false"],
  "must_contain": ["\"responseStatus\":\"OK\""]
}
```

| שדה | תיאור |
|---|---|
| `status` | קודי תשובה תקינים. טווח `"200-299"`, רשימה `"200,201"`, או שילוב `"200-204,304"` |
| `error_words` | אם אחד מהביטויים מופיע בתשובה, הריצה היא **כשל**. רשימה |
| `must_contain` | אם אחד מהביטויים **חסר** בתשובה, הריצה היא **כשל**. רשימה |

- **אותיות גדולות וקטנות:** החיפוש לא מבחין ביניהן.
- **התאמה מדויקת:** החיפוש הוא על הטקסט המדויק של התשובה. בתשובת JSON צפופה כותבים בלי רווחים: `"\"status\":\"ok\""`.

## rules: אילו מיילים לשלוח

כל כלל שולח מייל אחד. הכללים נבדקים לפי הסדר.

```json
{
  "name": "שם הכלל",
  "when": "success",
  "if": [
    { "field": "json:data.type", "op": "equals", "value": "vip" }
  ],
  "match": "all",
  "email": {
    "to": ["a@example.com", "b@example.com"],
    "cc": [],
    "subject": "נושא המייל",
    "body": "תוכן המייל",
    "html": false
  },
  "stop": false
}
```

| שדה | תיאור |
|---|---|
| `name` | שם לזיהוי (רשות) |
| `when` | `"always"` (תמיד), `"success"` (רק כשהצליח), `"failure"` (רק כשנכשל) |
| `if` | תנאים על התשובה (רשות, עד 20). ריק = אין תנאים |
| `match` | `"all"` = כל התנאים חייבים להתקיים. `"any"` = מספיק אחד |
| `email.to` | נמענים: רשימה, או מחרוזת מופרדת בפסיקים. חובה |
| `email.cc` | עותק (רשות) |
| `email.subject` | נושא. חובה |
| `email.body` | תוכן. חובה. טקסט רגיל, שורות נשמרות |
| `email.html` | `true` = התוכן הוא HTML (ערכים מהתשובה עוברים escape). ברירת מחדל `false` |
| `stop` | `true` = אם הכלל הזה התקיים, לא בודקים את הכללים שאחריו |

אפשר עד 30 כללים.

### תנאים (`if`)

**field**: מה בודקים:

| ערך | מה זה |
|---|---|
| `status` | קוד התשובה (למשל 200) |
| `body` | כל טקסט התשובה |
| `json:נתיב` | שדה מתוך תשובת JSON, למשל `json:data.status` או `json:items[0].name` |
| `header:שם` | כותרת בתשובה, למשל `header:content-type` |

**op**: איך משווים:

| ערך | משמעות |
|---|---|
| `equals` | שווה ל (מספרים מושווים כמספרים) |
| `not_equals` | שונה מ |
| `contains` | מכיל |
| `not_contains` | לא מכיל |
| `starts_with` | מתחיל ב |
| `gt` | גדול מ (מספר) |
| `lt` | קטן מ (מספר) |
| `exists` | קיים (בלי `value`) |
| `not_exists` | לא קיים (בלי `value`) |
| `regex` | תואם לביטוי רגולרי |

ההשוואות לא מבחינות בין אותיות גדולות וקטנות.

### "אם... אחרת..."

שמים קודם את הכלל המיוחד עם `"stop": true`, ואחריו את הכלל הכללי:

```json
"rules": [
  { "name": "VIP", "when": "success", "if": [{ "field": "json:type", "op": "equals", "value": "vip" }],
    "email": { "to": ["manager@x.com"], "subject": "...", "body": "..." }, "stop": true },
  { "name": "כל השאר", "when": "success",
    "email": { "to": ["team@x.com"], "subject": "...", "body": "..." } }
]
```

## משתנים

כותבים אותם בתוך `{{ }}`. אפשר להשתמש בהם בכתובת, בכותרות, בגוף הבקשה, ובנושא ובתוכן של המייל.

| משתנה | ערך |
|---|---|
| `{{date}}` | תאריך היום, `2026-11-03` |
| `{{time}}` | השעה, `10:30` |
| `{{datetime}}` | `2026-11-03 10:30` |
| `{{hebrew_date}}` | התאריך העברי, `ט״ו שבט תשפ״ז` |
| `{{timestamp}}` | Unix timestamp בשניות |
| `{{task}}` | שם המשימה |
| `{{secret:NAME}}` | ערך של Worker secret בשם NAME |

רק במיילים (אחרי שהתקבלה תשובה):

| משתנה | ערך |
|---|---|
| `{{result}}` | `הצליח` או `נכשל` |
| `{{status}}` | קוד התשובה |
| `{{json:נתיב}}` | שדה מתשובת JSON, למשל `{{json:data.count}}` |
| `{{header:שם}}` | כותרת מהתשובה |
| `{{response}}` | תחילת התשובה (עד 2000 תווים) |
| `{{error}}` | סיבת הכשל (טכנית) |

משתנה לא מוכר נשאר כמו שהוא.

## דוגמאות מלאות

### ימות המשיח: העתקת קובץ בכל ראש חודש אדר

ה-API של ימות המשיח עונה 200 גם כשיש שגיאה, לכן בודקים את `responseStatus`. הטוקן הוא `מספר_מערכת:סיסמה`.

```json
{
  "name": "העתקת הקובץ בימות המשיח",
  "enabled": true,
  "schedule": { "type": "yearly", "calendar": "hebrew", "month": "adar", "day": 1, "times": ["08:00"] },
  "request": {
    "method": "GET",
    "url": "https://www.call2all.co.il/ym/api/FileAction?token=0771234567:123456&action=copy&what=ivr2:1/000.wav&target=ivr2:2",
    "headers": {},
    "body": "",
    "timeout_seconds": 30,
    "retries": 2
  },
  "success": {
    "status": "200-299",
    "error_words": ["\"success\":false"],
    "must_contain": ["\"responseStatus\":\"OK\""]
  },
  "rules": [
    {
      "name": "הצליח",
      "when": "success",
      "if": [],
      "email": {
        "to": ["office@your-domain.com"],
        "subject": "בוצע בהצלחה: העתקת הקובץ בימות המשיח",
        "body": "שלום רב,\n\nרצינו לעדכן שבוצעה היום, {{hebrew_date}}, בשעה {{time}}, העתקת הקובץ בימות המשיח:\nהקובץ משלוחה 1 הועתק לשלוחה 2.\n\nאין צורך לעשות דבר.\n\nבברכה"
      }
    },
    {
      "name": "נכשל",
      "when": "failure",
      "if": [],
      "email": {
        "to": ["office@your-domain.com"],
        "subject": "לא הצליח: העתקת הקובץ בימות המשיח",
        "body": "שלום רב,\n\nהיום, {{hebrew_date}}, בשעה {{time}}, ניסינו להעתיק את הקובץ משלוחה 1 לשלוחה 2 בימות המשיח, אבל הפעולה לא הצליחה.\n\nמה כדאי לעשות:\n• לבדוק שהקובץ עדיין נמצא בשלוחה 1\n• לבדוק שמספר המערכת והסיסמה לא השתנו\n• אם הבעיה נמשכת, לפנות לאחראי על המערכת\n\nבברכה"
      }
    }
  ]
}
```

פקודות נפוצות של ימות המשיח (כתובת בסיס `https://www.call2all.co.il/ym/api/`):

| פעולה | כתובת |
|---|---|
| העתקת קובץ | `FileAction?token=...&action=copy&what=ivr2:1/000.wav&target=ivr2:2` |
| העברת קובץ | `FileAction?token=...&action=move&what=ivr2:1/000.wav&target=ivr2:2` |
| מחיקת קובץ | `FileAction?token=...&action=delete&what=ivr2:1/000.wav` |

את פקודת ההעתקה בדקנו מול דוגמאות בפורום של ימות המשיח. בהעברה ובמחיקה כדאי ללחוץ "בדיקה עכשיו" לפני השמירה.

התשובה של ימות המשיח היא JSON עם `responseStatus`: `OK` = הצליח, `ERROR` / `FORBIDDEN` / `EXCEPTION` = נכשל.

### בדיקה שאתר עובד כל 10 דקות

```json
{
  "name": "בדיקת האתר",
  "schedule": { "type": "interval", "minutes": 10 },
  "request": { "method": "GET", "url": "https://www.your-site.co.il", "timeout_seconds": 20, "retries": 1 },
  "success": { "status": "200-299" },
  "rules": [
    {
      "when": "failure",
      "email": {
        "to": ["office@your-domain.com"],
        "subject": "האתר לא עונה",
        "body": "שלום רב,\n\nבבדיקה היום בשעה {{time}} האתר לא ענה כראוי.\nכדאי לבדוק שהוא פועל.\n\nבברכה"
      }
    }
  ]
}
```

### API עם מפתח, כל בוקר בימים א׳-ה׳, ומייל לפי מה שחזר

```json
{
  "name": "דוח הזמנות יומי",
  "schedule": { "type": "daily", "times": ["08:00"], "days": [0, 1, 2, 3, 4] },
  "request": {
    "method": "POST",
    "url": "https://api.example.com/v1/orders/summary",
    "headers": { "Authorization": "Bearer YOUR_API_KEY" },
    "body": { "date": "{{date}}" }
  },
  "success": { "status": "200-299", "error_words": ["error"] },
  "rules": [
    {
      "name": "יש הזמנות פתוחות",
      "when": "success",
      "if": [{ "field": "json:open_orders", "op": "gt", "value": "0" }],
      "email": {
        "to": ["manager@your-domain.com"],
        "subject": "יש {{json:open_orders}} הזמנות פתוחות",
        "body": "בוקר טוב,\n\nנכון להיום ({{hebrew_date}}) יש {{json:open_orders}} הזמנות שעדיין לא טופלו.\n\nבברכה"
      },
      "stop": true
    },
    {
      "name": "הכל מטופל",
      "when": "success",
      "email": {
        "to": ["team@your-domain.com"],
        "subject": "אין הזמנות פתוחות",
        "body": "בוקר טוב,\n\nכל ההזמנות טופלו. יום טוב!"
      }
    }
  ]
}
```
