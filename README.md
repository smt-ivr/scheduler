# מתזמן משימות על Cloudflare Workers

מתזמן כללי שמריץ קריאות HTTP/API ושולח מיילים (דרך Resend) לפי לוח זמנים. הוא כולל ממשק ניהול בעברית שמוגש מאותו Worker.

## יכולות

- **תזמון**: ביטוי cron חוזר או מועד חד-פעמי. הכל לפי שעון ישראל (`Asia/Jerusalem`), כולל מעבר בין שעון קיץ לחורף.
  - שעה שלא קיימת ביום המעבר לשעון קיץ (למשל 02:30) רצה שעה מאוחר יותר.
  - שעה שמופיעה פעמיים ביום המעבר לשעון חורף רצה פעם אחת בלבד.
- **Cron Trigger אחד** שרץ כל דקה, בודק אילו משימות הגיע זמנן ומריץ אותן.
- **מניעת ריצה כפולה**: כל משימה ננעלת אטומית לפני שהיא מתחילה לרוץ. משימה שעדיין רצה לא תתחיל שוב, גם לא בלחיצה על "הרץ עכשיו". נעילה שנתקעה משתחררת אוטומטית אחרי 15 דקות.
- **משימה חד-פעמית** מושבתת אוטומטית אחרי שהיא רצה.
- **סודות**: אפשר לכתוב `{{secret:NAME}}` ב-URL, בכותרות, בגוף הבקשה ובמייל. הערך נלקח מ-Worker secret, לא נשמר במסד, ומוסתר (`***`) ביומן ובממשק.
- **משתנים דינמיים**:
  - `{{date}}` ו-`{{date:-1}}` (תאריך עם הזזה בימים)
  - `{{datetime}}`
  - `{{timestamp}}` ו-`{{timestamp_ms}}`
  - `{{iso}}`, `{{uuid}}`
  - `{{task_id}}`, `{{task_name}}`, `{{run_id}}`
- **ניסיונות חוזרים**: עד 5 ניסיונות (ברירת המחדל: 3). זמן ההמתנה מוכפל בכל פעם: 2 שניות, אחר כך 4 וכן הלאה.
- **בדיקת הצלחה**: אפשר להגדיר אילו קודי תגובה נחשבים תקינים (למשל `200-299,304`) וטקסט שהתגובה חייבת להכיל.
- **יומן ריצות**: לכל ריצה נשמרים זמן, קוד תגובה, משך, פירוט הניסיונות ותחילת התגובה. רשומות ישנות מ-30 יום (ניתן לשינוי) נמחקות אוטומטית.
- **התראה על כשל**: נשלחת ל-webhook (תואם ל-Slack ול-Discord) ו/או במייל, כשמשימה נכשלת סופית. אפשר להגדיר גם הודעה כשמשימה חוזרת לפעול.
- **מיילים דרך Resend**:
  - משימות מתוזמנות ששולחות מייל, ושליחה ידנית מהממשק.
  - מעקב מסירה, פתיחות ולחיצות דרך ה-webhook של Resend, עם ציר זמן לכל מייל.
- **ממשק ניהול**:
  - לוח בקרה עם גרף ריצות
  - משימות: הוספה, עריכה, שכפול, השבתה, מחיקה ופעולות על כמה משימות יחד
  - "הרץ עכשיו" ותצוגה מקדימה של הבקשה
  - בונה cron עם חמשת מועדי הריצה הבאים
  - יומן ריצות ויומן מיילים
  - הגדרות, ייצוא וייבוא של משימות, ויומן פעולות ניהול
  - הממשק מוגן בסיסמה ובהגבלת ניסיונות כניסה

## שמירה על המסד הקיים

המתזמן משתמש במסד `yemot-pay`, שמשמש גם מערכת אחרת בייצור:

- כל הטבלאות והאינדקסים שהמתזמן יוצר מתחילים ב-`scheduler_`.
- הקוד לא קורא ולא כותב לשום טבלה אחרת.
- ב-`wrangler.toml` מוגדר `migrations_table = "scheduler_migrations"`. בלי ההגדרה הזו, wrangler היה יוצר טבלת מעקב בשם `d1_migrations`.

## התקנה והעלאה

הפקודות רצות מהמחשב שלך, מתוך תיקיית הפרויקט.

### 1. התקנה והתחברות ל-Cloudflare

```bash
npm install
npx wrangler login
```

### 2. הגדרת סודות

כל פקודה תבקש להקליד את הערך. הערכים נשמרים ב-Cloudflare בלבד.

```bash
npx wrangler secret put ADMIN_PASSWORD       # סיסמת הכניסה לממשק
npx wrangler secret put RESEND_API_KEY       # המפתח מ-Resend (re_...)
npx wrangler secret put MY_API_TOKEN         # דוגמה לסוד של משימה, לשימוש כ-{{secret:MY_API_TOKEN}}
```

אם ה-Worker עדיין לא קיים, wrangler ישאל אם ליצור אותו. ענה כן.

### 3. הרצת ה-migration על המסד המרוחק

לפני ההרצה, אפשר לראות אילו migrations ממתינים. הפקודה הזו רק קוראת:

```bash
npx wrangler d1 migrations list yemot-pay --remote
```

ההרצה עצמה. היא יוצרת רק את טבלאות `scheduler_`:

```bash
npx wrangler d1 migrations apply yemot-pay --remote
```

### 4. העלאת ה-Worker

```bash
npx wrangler deploy
```

בסיום תתקבל כתובת בסגנון `https://scheduler.<your-subdomain>.workers.dev`. זו כתובת ממשק הניהול.

**חיבור לדומיין תחת נתיב** (למשל `https://smti.uk/scheduler`): ב-Cloudflare מוסיפים ל-Worker את ה-Route `smti.uk/scheduler*`. הנתיב מוגדר ב-`wrangler.toml` בשדה `BASE_PATH`, וכל הכתובות של הממשק מקבלות אותו כקידומת, כולל `/scheduler/webhooks/resend`.

### 5. מעקב מסירת מיילים (רשות, מומלץ)

1. ב-Resend: **Webhooks** ← **Add Endpoint**. הכתובת היא `https://smti.uk/scheduler/webhooks/resend` (או `https://scheduler.<your-subdomain>.workers.dev/webhooks/resend`), ובוחרים את כל אירועי `email.*`.
2. מעתיקים את ה-Signing Secret (`whsec_...`) ושומרים אותו כסוד:
   ```bash
   npx wrangler secret put RESEND_WEBHOOK_SECRET
   ```
3. בממשק, תחת **הגדרות**, ממלאים "כתובת שולח ברירת מחדל" מהדומיין שאומת ב-Resend.

## דוגמה: משימה מוגדרת

משימה שבימים ראשון עד חמישי, בשעה 07:30 לפי שעון ישראל, שולחת לשרת דוח של אתמול:

| שדה | ערך |
|---|---|
| שם | סנכרון הזמנות יומי |
| סוג | קריאת HTTP |
| תזמון | `30 7 * * 0-4` (בימים ראשון עד חמישי, בשעה 07:30) |
| שיטה וכתובת | `POST https://api.example.com/v1/reports/sync` |
| כותרות | `{"Authorization": "Bearer {{secret:MY_API_TOKEN}}"}` |
| גוף | `{"date": "{{date:-1}}", "requested_at": "{{datetime}}", "request_id": "{{uuid}}"}` |
| קודי תגובה תקינים | `200-299` |
| ניסיונות | 3 (המתנות של 2 ו-4 שניות) |
| מייל להתראת כשל | `ops@your-domain.com` |

אותה משימה בפורמט ייבוא. ראה את `examples/tasks.json` ואת הכפתור "ייבוא מקובץ" במסך ההגדרות.

## הערות

- בתוכנית החינמית של Workers יש מגבלה של 50 קריאות יוצאות לכל הפעלה. אם יש הרבה משימות שרצות באותה דקה, כדאי להוריד את "מקסימום משימות שמתחילות באותה דקה" בהגדרות, או לעבור לתוכנית בתשלום.
- משימה שפספסה את מועדה (למשל בגלל השהיה כללית) רצה פעם אחת כשהיא מתאפשרת. אחר כך היא ממשיכה מהמועד הבא, בלי "להשלים" את כל הפספוסים.
- הסודות `ADMIN_PASSWORD`, `RESEND_API_KEY` ו-`RESEND_WEBHOOK_SECRET` שמורים למערכת, ואי אפשר להפנות אליהם מתוך משימה.
