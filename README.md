# מתזמן משימות (Cloudflare Workers)

שולח בקשות HTTP במועדים שקובעים, בודק את התגובה, ושולח מיילים לפי מה שהתגובה מכילה.
הממשק נמצא ב-`https://smti.uk/scheduler`.

## מה יש

- **הגדרות מייל**: מפתח Resend, כתובת שולח וכתובת למענה. יש גם כפתור לשליחת מייל בדיקה.
- **משימות**: כל משימה היא JSON אחד. אפשר לערוך אותה בטופס או ישירות כ-JSON.
  - **מתי**: מועדים מסוימים, כל יום, כל חודש, כל שנה, או כל כמה דקות. חודש ושנה אפשר גם לפי לוח עברי. תאריך עברי מומר אוטומטית ללועזי.
  - **הבקשה**: שיטה, כתובת, כותרות (כולל מפתח API) וגוף.
  - **מתי זה הצלחה**: קודי תגובה תקינים, ומילים שאם הן מופיעות בתגובה זו שגיאה, גם כשהשרת עונה 200.
  - **כללים**: לפי התוצאה ולפי מה שיש בתגובה, איזה מייל לשלוח, למי ומה כתוב בו.
- **יומן ריצות**: כל ריצה עם התגובה והמיילים שנשלחו. נשמר 30 יום.
- **בדיקה עכשיו**: מריצה את הבקשה בלי לשמור ובלי לשלוח מיילים, ומראה אילו מיילים היו נשלחים ומה היה כתוב בהם.

כל הזמנים לפי שעון ישראל, כולל מעבר שעון קיץ/חורף. Cron אחד רץ כל דקה, ונעילה אטומית מונעת ריצה כפולה של אותה משימה.

## מדריך ל-AI

המדריך המלא למבנה ה-JSON, עם דוגמאות והוראות ל-AI, נמצא ב-`src/task-format.md`. אפשר לגשת אליו בשלוש דרכים:
- בממשק, בלשונית **תיעוד**. שם יש כפתורי הורדה והעתקה.
- בכתובת `https://smti.uk/scheduler/docs.md`.
- להורדה כקובץ: `https://smti.uk/scheduler/docs.md?download=1`.

## מבנה ה-JSON של משימה

```json
{
  "name": "שם המשימה",
  "enabled": true,
  "schedule": { ... },
  "request": {
    "method": "POST",
    "url": "https://api.example.com/endpoint?date={{date}}",
    "headers": { "Authorization": "Bearer YOUR_API_KEY" },
    "body": { "date": "{{date}}" },
    "timeout_seconds": 30,
    "retries": 2
  },
  "success": {
    "status": "200-299",
    "error_words": ["error", "שגיאה"],
    "must_contain": []
  },
  "rules": [
    {
      "name": "שם הכלל",
      "when": "always | success | failure",
      "if": [ { "field": "json:data.status", "op": "equals", "value": "ok" } ],
      "match": "all | any",
      "email": { "to": ["a@x.com"], "cc": [], "subject": "...", "body": "...", "html": false },
      "stop": false
    }
  ]
}
```

### schedule: מתי לרוץ

| סוג | דוגמה |
|---|---|
| מועדים מסוימים | `{"type": "dates", "dates": ["2026-11-03 10:30", "2026-11-05 18:00"]}` |
| כל יום / ימים נבחרים | `{"type": "daily", "times": ["08:00", "20:00"], "days": [0,1,2,3,4]}` (0 = ראשון) |
| כל חודש, לועזי | `{"type": "monthly", "calendar": "gregorian", "day": 1, "times": ["09:00"]}` |
| כל חודש, עברי | `{"type": "monthly", "calendar": "hebrew", "day": 1, "times": ["07:00"]}` (ראש חודש) |
| כל שנה, לועזי | `{"type": "yearly", "calendar": "gregorian", "month": 3, "day": 15, "times": ["09:00"]}` |
| כל שנה, עברי | `{"type": "yearly", "calendar": "hebrew", "month": "שבט", "day": 15, "times": ["10:00"]}` |
| כל כמה דקות | `{"type": "interval", "minutes": 30, "from": "08:00", "to": "20:00", "days": [0,1,2,3,4]}` |

- לכל סוג חוזר אפשר להוסיף `"start_date"` ו-`"end_date"` (פורמט `2026-11-01`).
- משימת `dates` מושבתת אוטומטית אחרי המועד האחרון.
- יום שלא קיים בחודש נופל על היום האחרון של החודש. למשל 31 בחודש של 30 יום, או ל׳ בחודש עברי של 29 יום.
- חודש עברי אפשר לכתוב בשם עברי (`"ניסן"`, `"אדר ב"`) או באנגלית (`"nisan"`, `"adar2"`).
  - בשנה פשוטה, אדר א׳ ואדר ב׳ הם אדר.
  - בשנה מעוברת, "אדר" הוא אדר ב׳.
- התאריך העברי נקבע לפי היום האזרחי (מחצות), לא לפי השקיעה.
- `minutes` יכול להיות 1, 2, 5, 10, 15, 20, 30, 60, 120, 180, 240, 360 או 720.

### request: הבקשה

- `body` יכול להיות טקסט או אובייקט JSON.
- כשהגוף הוא JSON, המשתנים מוחלפים בתוך הערכים בצורה בטוחה, כך שגרשיים בערך לא ישברו את ה-JSON.
- `retries`: כמה פעמים לנסות שוב כשאין תשובה או כשהקוד לא תקין, בהמתנה של 2 שניות, אחר כך 4 וכן הלאה.
  כשהשגיאה זוהתה לפי מילה בתוכן לא מנסים שוב, כי השרת ענה בבירור.

### success: מתי זה הצלחה

- `status`: קודי התגובה התקינים, למשל `"200-299"` או `"200,201"`.
- `error_words`: אם אחת מהמילים מופיעה בתגובה, הריצה נחשבת כשל. לא משנה אם באותיות גדולות או קטנות.
- `must_contain`: מילים שחייבות להופיע בתגובה, אחרת זה כשל.

### rules: מה לשלוח לפי התגובה

- `when`: מתי הכלל נבדק. `always` (תמיד), `success` (רק כשהריצה הצליחה) או `failure` (רק כשנכשלה).
- `if`: תנאים על התגובה. ריק = אין תנאים.
  - `field` הוא החלק בתגובה שבודקים:
    - `status`: קוד התגובה.
    - `body`: כל גוף התגובה.
    - `json:path`: שדה מתוך תגובת JSON, למשל `json:data.items[0].status`.
    - `header:name`: כותרת מהתגובה.
  - `op` היא ההשוואה: `equals`, `not_equals`, `contains`, `not_contains`, `starts_with`, `gt`, `lt`, `exists`, `not_exists`, `regex`.
- `match`: `all` = כל התנאים חייבים להתקיים. `any` = מספיק תנאי אחד.
- `stop: true`: אם הכלל הזה התקיים, לא בודקים את הכללים שאחריו. כך בונים "אם... אחרת...".
- `email.html: false`: התוכן הוא טקסט רגיל, והשורות נשמרות. ב-`true` התוכן נשלח כ-HTML, וערכים מהתגובה עוברים escape.

### משתנים

אפשר להשתמש בהם בכתובת, בכותרות, בגוף, ובנושא ובתוכן של המייל:

| משתנה | ערך |
|---|---|
| `{{date}}` / `{{time}}` | תאריך / שעה בישראל |
| `{{hebrew_date}}` | ט״ו שבט תשפ״ז |
| `{{timestamp}}` | Unix timestamp |
| `{{task}}` | שם המשימה |
| `{{result}}` | הצליח / נכשל (במיילים) |
| `{{status}}` | קוד התגובה (במיילים) |
| `{{json:path}}` | שדה מהתגובה (במיילים) |
| `{{response}}` | תחילת התגובה (במיילים) |
| `{{error}}` | סיבת הכשל (במיילים) |
| `{{secret:NAME}}` | ערך של Worker secret, למי שמעדיף לא לשמור מפתח בתוך המשימה |

## דוגמה מלאה

ראה `examples/task.json`. היא בודקת מנויים בכל ראש חודש עברי בשעה 08:00, ושולחת:
- למנהל: מייל אם יש חריגה.
- לצוות: מייל אם הכל תקין.
- למשרד: מייל אם הייתה שגיאה.

## התקנה

```bash
npm install
npx wrangler login
npx wrangler secret put ADMIN_PASSWORD               # סיסמת הכניסה לממשק
npx wrangler d1 migrations apply yemot-pay --remote  # טבלאות scheduler_ בלבד
npx wrangler deploy
```

את מפתח Resend וכתובת השולח מגדירים בממשק, בלשונית "הגדרות מייל".

## הערות

- **מפתחות במסד**: מפתחות API שכותבים בתוך משימה, וגם מפתח Resend, נשמרים במסד D1. מי שמעדיף שלא יישמרו שם יכול להשתמש ב-`{{secret:NAME}}`.
- **מה נשמר ביומן**: הכתובת נשמרת בלי הפרמטרים שלה, כדי שמפתח שמופיע בכתובת לא יישמר. נשמרים גם 2000 התווים הראשונים של התגובה.
- **המסד המשותף**: המתזמן משתמש רק בטבלאות שמתחילות ב-`scheduler_`, במסד `yemot-pay`. גם טבלת המעקב של wrangler היא `scheduler_migrations`.

## פיתוח מקומי

echo "ADMIN_PASSWORD=test" > .dev.vars
